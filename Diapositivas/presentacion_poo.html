📐 Diagrama de Clases UML

Definición Formal: Representación estática del sistema que modela clases, interfaces, atributos, operaciones y sus relaciones. Es un pilar del Lenguaje Unificado de Modelado (UML 2.5, OMG).

Componentes Clave

  • Clases: Abstracciones de entidades, representadas en 3 secciones (Nombre, Atributos, Métodos).
  • Visibilidad: Control de acceso: + (public), # (protected), - (private), ~ (package).
  • Relaciones: Vínculos entre clases: Herencia (△), Asociación (→), Composición (◆), Agregación (◇).
  • Multiplicidad: Define la cardinalidad de las relaciones (e.g., 1..*, 0..1).

🗄️ Normalización de Bases de Datos

Teoría de Codd (1970): Proceso sistemático para organizar las columnas y tablas de una base de datos relacional para minimizar la redundancia de datos y evitar anomalías de manipulación (inserción, actualización, borrado).

Formas Normales Principales

Forma NormalRequisito FundamentalObjetivo
1FNTodos los atributos son atómicos.Eliminar grupos repetitivos.
2FNCumple 1FN y no existen dependencias parciales.Asegurar que cada atributo dependa de la clave completa.
3FNCumple 2FN y no existen dependencias transitivas.Eliminar dependencias entre atributos no clave.
BCNFCumple 3FN y toda determinante es una clave candidata.Resolver anomalías no cubiertas por 3FN.

🧬 Herencia: Reutilización y Polimorfismo

Relación "es un/a" (IS-A): Mecanismo que permite a una nueva clase (subclase) adquirir los atributos y métodos de una clase existente (superclase), permitiendo la reutilización de código y la creación de jerarquías.

Conceptos Clave

  • Sobrescritura de Métodos (Overriding): Una subclase puede proporcionar una implementación específica de un método que ya es provisto por su superclase.
  • Polimorfismo: Capacidad de un objeto para tomar muchas formas. Una variable de tipo superclase puede referenciar un objeto de cualquiera de sus subclases.
  • Clases Abstractas: Clases que no pueden ser instanciadas y que sirven como base para otras clases, pudiendo definir métodos abstractos (sin implementación).

Principio de Diseño: "Favorecer la composición sobre la herencia" para evitar jerarquías rígidas y frágiles. La herencia debe usarse solo cuando la relación "IS-A" es conceptualmente correcta.

Estrategias de Mapeo Objeto-Relacional (JPA)

  • Single Table: Una sola tabla para toda la jerarquía, con una columna discriminadora. Rápida pero puede tener muchos nulos.
  • Joined Table: Una tabla por cada clase en la jerarquía, unidas por claves foráneas. Normalizada pero requiere más JOINs.
  • Table Per Class: Una tabla por cada clase concreta, sin relación a nivel de BD. No soporta bien polimorfismo.

🎓 Conclusiones

Síntesis de Conceptos

La combinación sinérgica de diagramas UML, normalización, herencia y encapsulación es la base de la arquitectura de software moderna, robusta y mantenible.

  • UML es el lenguaje para visualizar la arquitectura.
  • La Normalización garantiza la salud de los datos.
  • La Herencia y la Encapsulación estructuran el código de forma lógica y segura.

Impacto en el Desarrollo

Un diseño que integra correctamente estos principios conduce a sistemas que son:

  • Mantenibles: Cambios en un componente tienen un impacto mínimo en otros.
  • Escalables: Es más fácil añadir nueva funcionalidad sin romper la existente.
  • Seguros: El estado interno de los objetos está protegido contra modificaciones indebidas.
